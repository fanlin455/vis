期末:从数据到发布

一个可视化项目的完整生命:选题 → 找数据 → 清洗 → 探索 → 设计 → 实现 → 发布 → 迭代。 本章把前八章的技能串成流水线,并用 GitHub Pages 把作品免费送到互联网上—— 能被别人打开的图,才算画完了。

KP 9.1

六步工作流:每一步都有产出物

新手最常见的翻车:拿到数据立刻打开编辑器写代码。正确的顺序是—— 先想清楚给谁看、回答什么问题,数据、图表、交互都为这个问题服务。

💡 口诀:问题 > 数据 > 图 > 代码。顺序反了,返工是必然。

KP 9.2

GitHub Pages:五分钟上线作品

GitHub Pages 对静态网站免费:推一个仓库上去,开一个开关,你的作品就有了 https://用户名.github.io/仓库名 的公网地址。本课程门户就是这么发布的。

⚠️ Pages 只适合纯静态内容(HTML/CSS/JS/数据文件):没有后端、不能跑数据库; 单文件建议 < 100MB、整仓 < 1GB——这也是本站坚持"零视频、轻依赖"的原因(呼应第 1 章)。
deploy.sh
# 1. 建仓并初始化(仓库名即网址后缀)
git init
git add .
git commit -m "feat: 课程作品 v1"

# 2. 推送到 GitHub(先在网页上创建空仓库)
git branch -M main
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main

# 3. 开启 Pages:仓库 Settings → Pages
#    Source 选 main 分支 /root,Save
#    ⏳ 约 1 分钟后访问 https://<用户名>.github.io/<仓库名>/

# 以后每次更新只需:
git add . && git commit -m "update" && git push   # 推送即部署
