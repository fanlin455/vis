D3.js 常用图表

柱、线、散点、饼是统计图表的"四大金刚"。它们不是四种画法, 而是四种提问方式:谁大谁小?趋势如何?两件事有关吗?份额怎么分? 选错图表类型,再多美化也救不回来——先问对问题,再动手画图。

柱状图折线图散点图饼图图表选择

🎯 学习目标

  • 掌握四大图表各自的适用问题与禁忌场景
  • 能为柱状图/折线图添加悬停提示与平滑重排动画
  • 理解散点图的"颜色 = 类别、位置 = 两个变量"编码方式
  • 知道饼图的使用边界(类目数 ≤ 5,占比差异明显)
KP 3.1

柱状图:比较大小

柱状图回答"分类 × 数值"的比较问题:哪个类目最大?差距多大? 人眼对"长度"的判断极其精确(感知精度仅次于位置),这是柱状图成为默认选择的根本原因。

  • 柱宽一致、柱间距约柱宽的 20%~40%,比较才公平
  • y 轴必须从 0 开始——截断 y 轴会放大差异,制造误导
  • 类目多且无序时,提供"按数值排序"比原顺序更有洞察力
💡 本站路径图的节点、第 1 章的加载进度,本质上都是"柱状思维":用长度编码数量。
bar-chart.js
const x = d3.scaleBand()                    // 类目轴:每类占一个"带"
  .domain(data.map(d => d.month))
  .range([PAD, W - PAD])
  .padding(0.3);

const y = d3.scaleLinear()
  .domain([0, d3.max(data, d => d.value)])  // 柱状图 y 从 0 开始!
  .range([H - PAD, PAD]);

svg.selectAll("rect")
  .data(data, d => d.month)
  .join("rect")
  .transition().duration(500)               // 数据换序时平滑重排
  .attr("x", d => x(d.month))
  .attr("y", d => y(d.value))
  .attr("width", x.bandwidth())
  .attr("height", d => y(0) - y(d.value));

演示 · 门店月销量(悬停看数值 · 点击排序)

提示:点击「切换排序」观察柱子的交换动画——排序后"哪个月最好卖"一眼可见,这正是排序带来的洞察。
KP 3.2

折线图:看趋势

折线图回答"随某个连续变量(通常是时间)如何变化"的问题。 它的核心是斜率:读者看的是线段的陡缓,不是点的高低—— 上升多快?哪里突变?有没有周期性?

  • 折线数量 ≤ 4~5 条;太多线互相交叉,谁都看不清
  • x 轴点距必须与时间间隔成比例,否则趋势失真
  • 面积图是折线的变体:线与轴之间填充,强调"累计量",适合单一序列
💡 悬停十字准线(crosshair)是折线图最实用的交互:把"某个时刻的值"精确地送到鼠标边。
line-chart.js
const line = d3.line()
  .x(d => x(d.month))              // 位置比例尺
  .y(d => y(d.temp))
  .curve(d3.curveMonotoneX);       // 单调样条:平滑但不"过冲"

const area = d3.area()
  .x(d => x(d.month))
  .y0(y(0))                        // 面积从基线(0)铺到
  .y1(d => y(d.temp));

svg.append("path")
  .datum(data)
  .attr("d", line)                 // 一条指令画出整条折线
  .attr("fill", "none")
  .attr("stroke", "#2f6fed");

演示 · 月平均气温(移动鼠标,十字准线取值)

提示:注意 y 轴域随城市数据自动重算——气温范围不同的两条曲线,都能恰好铺满画布。
KP 3.3

散点图:找关系

散点图一次编码两个(甚至更多)连续变量:x 是一个、y 是另一个, 点的疏密与走向揭示两者的关系——相关、聚类、离群点,一图全览。

  • 位置是感知精度最高的视觉通道,散点图把它用到了极致
  • 第三个变量可以用颜色(类别)或大小(数值)编码,再多就该慎重
  • 几百点以上注意"过度绘制"(点叠成一团),可调透明度或换 Canvas(第 4 章)
💡 交互要点:悬停看坐标是基本盘;图例点击过滤、框选联动(第 5 章)是进阶。
scatter.js
const x = d3.scaleLinear().domain(d3.extent(data, d => d.height)).range([PAD, W - PAD]);
const y = d3.scaleLinear().domain(d3.extent(data, d => d.weight)).range([H - PAD, PAD]);

svg.selectAll("circle")
  .data(data)
  .join("circle")
  .attr("cx", d => x(d.height))
  .attr("cy", d => y(d.weight))
  .attr("r",  5)
  .attr("fill", d => color(d.group))     // 颜色 = 类别
  .attr("fill-opacity", 0.75);             // 半透明,缓解重叠

演示 · 身高与体重(点我高亮同组 · 图例可过滤)

篮球组 游泳组 棋类组
提示:点击任一点,同组点亮、其他变暗——散点图的"组内模式"瞬间凸显。再点图例试试整组过滤。
KP 3.4

饼图:看占比

饼图回答"部分占整体的比例"。人眼对角度的感知精度其实不高, 所以饼图的使用边界比想象中窄:

  • 类目数 ≤ 5 为宜;超过 7 类请改用柱状图
  • 占比差异 < 5° 的扇区几乎无法分辨——相邻份额接近时,柱状图更诚实
  • 环形图(donut)中心可以放总量的 KPI 数字,信息密度更高,是饼图的首选变体
  • 扇区从 12 点方向顺时针、按占比降序排列,阅读最省力
⚠️ 不要把多张饼图并排比较——人眼无法跨图比较角度。要比较两个"份额构成",用堆叠柱状图。
pie.js
const pie = d3.pie()
  .value(d => d.share)
  .sortValues((a, b) => b - a);      // 降序排列,阅读省力

const arc = d3.arc()
  .innerRadius(55)                   // >0 即成环形图
  .outerRadius(90)
  .cornerRadius(4)
  .padAngle(0.02);                   // 扇区间留缝,更现代

svg.selectAll("path")
  .data(pie(data))
  .join("path")
  .attr("d", arc)                    // 弧形路径由 arc 生成器算好
  .attr("fill", d => color(d.index));

演示 · 浏览器市场份额(悬停扇区 · 点击图例剔除重算)

提示:点击图例剔除某家浏览器,其余份额自动重新归一化——体会"占比永远是相对于整体"。
