Canvas 绘图基础

SVG 是"保留模式":每个图形是 DOM 元素,浏览器替你管理;Canvas 是"立即模式": 拿到画笔一笔一笔画,画完就只剩像素。没有最好的技术,只有匹配数据规模的选型—— 几百个元素选 SVG 享受交互便利,几千上万个点选 Canvas 换取性能。

KP 4.1

SVG 还是 Canvas?一张表 + 一场赛跑

两种渲染模型的本质区别:

  • SVG = 保留模式(Retained Mode):你声明"这里有个圆",浏览器保存它。每个圆是 DOM 节点,可绑定事件、加 CSS——代价是元素一多,DOM 管理开销爆炸。
  • Canvas = 立即模式(Immediate Mode):你说"画个圆",浏览器画完就忘。只剩像素,没有个体可交互——换来的是,画一万个圆也只花一次栅格化的时间。
💡 粗略经验值:< 1,000 个可交互元素用 SVG;数据点成千上万(散点墙、轨迹、粒子)用 Canvas; 百万级(大规模地理、3D)上 WebGL(第 7 章的工具选型会再遇到它)。
engine-compare.js
// 同样画 N 个运动粒子,两种引擎的写法
// SVG:每个粒子一个  DOM 元素,每帧改属性
circles.forEach((c, i) => {
  c.setAttribute("cx", pos[i].x);   // 触发 DOM 属性更新
  c.setAttribute("cy", pos[i].y);   // × N 个元素 × 每帧
});

// Canvas:每帧清屏重画,没有任何 DOM 参与
function frame() {
  ctx.clearRect(0, 0, W, H);        // 1. 擦掉上一帧
  for (const p of particles) {
    ctx.beginPath();                // 2. 开始一条路径
    ctx.arc(p.x, p.y, p.r, 0, 6.28);// 3. 圆弧
    ctx.fill();                     // 4. 填充 —— 画完即忘
  }
  requestAnimationFrame(frame);
}

KP 4.2

画笔上手:基本绘制指令

Canvas 的 API 像一支画笔的工作流程:选颜色 → 起笔(path)→ 落笔(描/填)。 所有复杂图形都从 beginPath() 开始,到 fill() 或 stroke() 结束; 中间用 moveTo / lineTo / arc / rect 描述路径。

  • fillStyle / strokeStyle:填充色 / 描边色(支持 rgba,做出半透明叠加)
  • lineWidth / lineCap / lineJoin:线宽与端点样式(手绘感的关键)
  • 坐标体系与 SVG 一致:左上原点、y 向下; 高分屏需按 devicePixelRatio 放大画布再缩小 CSS 尺寸,否则模糊
canvas-draw.js
const ctx = canvas.getContext("2d");

ctx.strokeStyle = "#2f6fed";          // 描边色
ctx.lineWidth = 6;
ctx.lineCap = "round";                // 端点圆润,笔画自然
ctx.lineJoin = "round";

canvas.addEventListener("pointermove", (e) => {
  if (e.buttons !== 1) return;        // 仅按住左键时绘制
  ctx.beginPath();
  ctx.moveTo(lastX, lastY);           // 从上一点
  ctx.lineTo(e.offsetX, e.offsetY);   // 画到当前点
  ctx.stroke();                       // 落笔
  [lastX, lastY] = [e.offsetX, e.offsetY];
});

// 高分屏适配:物理像素放大,CSS 尺寸不变
const dpr = window.devicePixelRatio || 1;
canvas.width  = cssW * dpr;
canvas.height = cssH * dpr;
ctx.scale(dpr, dpr);

KP 4.3

动画循环:requestAnimationFrame

Canvas 动画的公式只有一行:擦掉 → 算新位置 → 画上 → 下一帧再来。 驱动这一循环的正确工具是 requestAnimationFrame(rAF), 它把回调排队到浏览器下一次重绘之前执行。

为什么不用 setInterval(fn, 16)?

  • rAF 与屏幕刷新自动同步(60/120Hz 都对),setInterval 的 16ms 只是猜测
  • 后台标签页自动暂停,不浪费电;setInterval 会照常空转
  • 动画基于时间差 dt 计算,而不是假设"每帧恰好 16ms"——帧率波动时速度依然稳定
⚠️ 记住公式 x += v * dt,其中 dt 是距上一帧的真实秒数。写死 x += 1 的动画,在 120Hz 屏上会跑两倍快。
anim-loop.js
let last = performance.now();

function loop(now) {
  const dt = (now - last) / 1000;     // 真实时间差(秒)
  last = now;

  ctx.clearRect(0, 0, W, H);
  for (const ball of balls) {
    ball.x += ball.vx * dt;           // 速度 × 时间,帧率无关
    ball.y += ball.vy * dt;
    if (ball.x < ball.r || ball.x > W - ball.r) ball.vx *= -1;   // 碰壁反弹
    if (ball.y < ball.r || ball.y > H - ball.r) ball.vy *= -1;

    ctx.beginPath();
    ctx.arc(ball.x, ball.y, ball.r, 0, Math.PI * 2);
    ctx.fillStyle = ball.color;
    ctx.fill();
  }
  requestAnimationFrame(loop);        // 排队下一帧
}
requestAnimationFrame(loop);
