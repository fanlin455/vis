交互进阶与动画

静态图回答一个问题,交互式可视化让读者不断提出新问题。 本章三件套——过渡、拖拽、刷选——是几乎所有高级交互的原子能力。 一条铁律贯穿始终:动画和交互必须服务于理解数据,炫技即噪音。

transitiond3.dragd3.brush联动动画原则

  • 会用 transition().duration().delay() 制作属性补间动画
  • 掌握指针事件(pointerdown/move/up)实现自定义拖拽,理解 pointer 事件优于 mouse 事件
  • 实现"刷选高亮 + 下方直方图联动"的经典组合交互
  • 建立动画时长与缓动的设计直觉(250–750ms,ease-in-out)
KP 5.1

过渡动画:让数据变化可追溯

数据从 A 状态变为 B 状态,若直接替换,读者看到的是"两张图"; 加上过渡(transition),读者看到的是"同一批元素的移动"—— 哪根柱子变长了、谁超过了谁,变化过程本身成为信息。

  • duration(ms):一次完整过渡时长,250~750ms 是公认舒适区
  • delay(ms):延迟启动;按索引递增 delay(i => i * 30) 产生"波浪式"错落感
  • 默认缓动 cubic-in-out(慢-快-慢)最自然;线性动画只适合进度条类场景
  • 过渡期间属性被锁定,再次触发会排队——数据高频更新时要 .interrupt()
💡 判断标准:读者能否从动画中读出"谁变了、怎么变的"?读不出就删掉。装饰性动画一律属于噪音。
transition.js
svg.selectAll("rect")
  .data(newData, d => d.key)          // 按 key 配对,元素有身份
  .join("rect")
  .transition()                        // 之后的属性变化全部做补间
  .duration(600)                       // 600ms,舒适区中段
  .delay((d, i) => i * 40)             // 逐根错落启动
  .ease(d3.easeCubicInOut)             // 慢-快-慢
  .attr("y", d => y(d.value))          // 旧值 → 新值自动补间
  .attr("height", d => y(0) - y(d.value));

// 多段过渡:先移动,再变色
rect.transition().duration(400).attr("y", newY)
    .transition().duration(200).style("fill", "crimson");

KP 5.2

事件与拖拽:把控制权交给用户

D3 的 .on() 绑定事件,和原生 DOM 一致但可直接链在选择集上。 d3.drag() 把 pointerdown / move / up 三件套封装成"拖拽行为", 挂到元素上即获得拖拽能力,拖拽期间自动处理坐标换算。

  • 统一用 pointer 系事件(pointerdown/move/up):鼠标、触屏、手写笔一套通吃,已被各浏览器支持
  • 拖拽时要"抓住"元素:on("start") 记录起点偏移,避免元素"跳"到指针位置
  • SVG 坐标 ≠ 屏幕坐标,用 d3.pointer(event, svg) 换算;缩放视图下尤其如此
  • 拖拽后记得做边界约束,别让元素被拖出画布找不回来
drag.js
const drag = d3.drag()
  .on("start", (event, d) => {
    d.dx = event.x - d.x;              // 记录指针与圆心的偏移
    d.dy = event.y - d.y;
  })
  .on("drag", (event, d) => {
    d.x = event.x - d.dx;              // 应用偏移,圆不"跳"
    d.y = event.y - d.dy;
    d.x = Math.max(R, Math.min(W - R, d.x));   // 边界约束
    d.y = Math.max(R, Math.min(H - R, d.y));
    d3.select(this).attr("cx", d.x).attr("cy", d.y);
  });

svg.selectAll("circle").call(drag);    // 一行挂载拖拽行为

KP 5.3

刷选与联动:一图提问,众图回答

刷(brush)是"用鼠标画一个框"的选择交互。d3.brush() 提供框选与移动, 真正的价值在于联动:框住的点在散点图里高亮, 同时下方直方图只统计框内样本——用户的一次动作,所有视图同时响应。

  • 刷选内 = 前景(高亮),刷选外 = 背景(变暗),对比度即答案
  • 联动本质是一个状态(selectionSet)广播给所有视图,视图各自重绘
  • 点击空白处清空刷选;按住刷框可拖动微调——这些细节决定手感
  • 联动视图不宜超过 3~4 个,响应延迟超过 100ms 联动感即被破坏
💡 刷选 + 联动是"探索式分析"的核心交互,Tableau、Observable、各大 BI 工具的"筛选器"皆源于此模式。
brush-linked.js
const brush = d3.brush()
  .extent([[0, 0], [W, H]])
  .on("start brush end", ({ selection }) => {
    // selection 为 null 表示清空;否则是 [[x0,y0],[x1,y1]]
    const selected = selection
      ? points.filter(([x, y]) =>
          x >= selection[0][0] && x <= selection[1][0] &&
          y >= selection[0][1] && y <= selection[1][1])
      : points;

    // 视图 1:散点 —— 命中高亮,未命中变暗
    dots.attr("opacity", d => isSelected(d) ? 0.9 : 0.08);

    // 视图 2:直方图 —— 只统计选中样本
    hist.data(bin(selected)).attr("y", ...).attr("height", ...);

    counter.text(selected.length + " / " + points.length);   // 计数反馈
  });

svg.call(brush);
